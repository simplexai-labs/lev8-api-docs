title: "Contact Search"

[`POST /v1/contact-search`](/api-reference/contact-search/search) searches for one email address or phone number and returns a JSON response.

## Headers

| Header | Required | Description |
| --- | --- | --- |
| `Content-Type: application/json` | Yes | Other media types return `422`. |
| `Accept: application/json` | Recommended | Declares that the client expects a JSON response. |
| `Authorization` | Yes | `Bearer lev8_live_...` — an active Lev8 API key with Contact Search access. |
| `Idempotency-Key` | Recommended | A stable value up to 128 characters for this logical lookup. |

## Request body

| Field | Type | Required | Constraints |
| --- | --- | --- | --- |
| `contact_type` | string | Yes | `email` or `phone`. |
| `objective` | string | Yes | Natural-language description of the owner and the email or phone number to find, 1 to 4,000 Unicode characters after trimming. |

The complete request body must be at most 1 MiB. Unknown fields, malformed JSON, and multiple JSON objects are rejected.

### Write the objective

<Tip>
  Include identity signals that help Lev8 identify the contact owner. For example, add `linkedin_url`, a company or personal website, X/Twitter, YouTube, TikTok, Instagram, or GitHub links or handles. More specific owner signals improve match accuracy.
</Tip>

curl "https://app.lev8.com/v1/contact-search" \
  --request POST \
  --header "Content-Type: application/json" \
  --header "Accept: application/json" \
  --header "Authorization: Bearer $LEV8_API_KEY" \

```python Python
import asyncio
import json
import os
import uuid
import httpx


API_URL = "https://app.lev8.com/v1/contact-search"
API_KEY = os.environ["LEV8_API_KEY"]


async def contact_search() -> None:
    headers = {
        "Content-Type": "application/json",
        "Accept": "application/json",
        "Authorization": f"Bearer {API_KEY}",
        "Idempotency-Key": str(uuid.uuid4()),
    }
    payload = {
        "contact_type": "email",
        "objective": "Find the work email of Jane Smith, VP of Engineering at Acme Corp. Owner signals: linkedin_url=https://www.linkedin.com/in/jane-smith-acme",
    }

    async with httpx.AsyncClient(timeout=60) as client:
        response = await client.post(API_URL, headers=headers, json=payload)
        request_id = response.headers.get("x-request-id")
        if response.is_error:
            try:
                message = response.json().get("error", {}).get("message")
            except (json.JSONDecodeError, UnicodeDecodeError):
                message = None
            raise RuntimeError(
                message
                or f"lev8 request failed with HTTP {response.status_code} "
                f"(request_id={request_id or 'unknown'})"
            )

        result = response.json()
        print(
            {
                "request_id": request_id,
                "content": result.get("result", {}).get("content"),
                "reference": result.get("result", {}).get("reference"),
            }
        )


if __name__ == "__main__":
    asyncio.run(contact_search())
```

## Response

On success, the response status is `200`. `Idempotency-Key` contains the supplied or server-generated retry key, `X-Request-Id` contains the lev8 request ID, and `Cache-Control` is `no-store`.

```json
{
  "object": "contact_search_result",
  "request": {
    "contact_type": "email",
    "objective": "Find the work email of Jane Smith, VP of Engineering at Acme Corp. Owner signals: linkedin_url=https://www.linkedin.com/in/jane-smith-acme"
  },
  "result": {
    "content": "jane.smith@acmecorp.com",
    "reference": "..."
  },
  "created_at": "2026-07-29T00:00:00Z"
}
```

| Field | Type | Description |
| --- | --- | --- |
| `object` | string | Always `contact_search_result`. |
| `request.contact_type` | string | Echoes the normalized `contact_type` from the request. |
| `request.objective` | string | Echoes the normalized `objective` from the request. |
| `result.content` | string or null | The email address or phone number when `outcome=found`; otherwise `null`. |
| `result.reference` | string or null | A supporting reference when available; otherwise `null`. |
| `created_at` | string | UTC RFC 3339 timestamp for the result. |

Clients should treat `result.content` as not found when it is `null`, empty, contains only whitespace, or is the legacy sentinel `unknown`. A returned candidate does not prove that the requested person or work mailbox was found. Inspect `owner_match_state`, `mailbox_type`, and the evidence before using it.

### Email search guidance

When present, the following optional fields explain an email lookup. Older responses and stored replays may omit them. Missing guidance means evidence is unavailable; it does not mean the search exhausted every available source.

| Field | Meaning |
| --- | --- |
| `result.assessment.satisfies_request` | `false` when evidence shows the result does not satisfy the request; `null` when the service cannot establish that all requested constraints are satisfied. Do not interpret `null` as `true`. |
| `result.assessment.reason_code` | A machine-readable reason for the assessment. |
| `result.search_summary` | Versioned, bounded execution evidence: resolved route, coverage, stop reason, elapsed milliseconds, cache status, and sanitized execution chain and steps. |
| `result.next_action` | Recommended action, reason, whether repeating the same input is worthwhile, and the kinds of new evidence needed. |
| `result.alternatives` | Up to three additional email candidates, with their own ownership and reliability evidence. Alternatives do not change the primary outcome or billing. |

`search_summary.coverage` distinguishes `complete`, `partial`, and `unknown`. Completion is limited to the current inputs and execution scope; it never proves that an email does not exist elsewhere. A timeout is incomplete work. A successful `not_found` result alone does not establish complete coverage. `trace_truncated=true` means some execution detail was omitted.

Inspect `next_action.action` before another lookup:

- `use_result`: use the result after checking its assessment.
- `stop`: stop the current search.
- `search_with_new_evidence`: obtain the evidence described by `required_evidence` before another search.
- `retry_later`: follow the existing error/retry contract and wait before retrying.
- `review_evidence`: review the result against the user's constraints; the service cannot make the final decision.

When `same_input_retry=not_recommended`, changing only the wording of `objective` or supplying a new key is not a useful next step. New, verified identity or employment evidence can justify a new search. A known mailbox can become owner-bound when new evidence arrives; the same mailbox text alone does not make two requests equivalent.

A shared company mailbox may be useful for organization outreach while failing a decision-maker request. A profile-bound personal mailbox may still fail a work-email request. A difference between website and mailbox domains requires evidence review rather than automatic rejection.

The execution summary omits raw provider payloads and internal errors. An HTTP or transport failure without a terminal response cannot establish search coverage.

## Billing behavior

Lev8 reserves the configured price for one lookup before contacting the search service. The request is charged only for a `found` outcome with a non-empty contact value; a completed lookup with no result releases the reservation. The assessment and ownership fields do not change this billing rule. Your Lev8 contact will provide the enabled contact types and applicable pricing.

The success response is written only after settlement succeeds. An upstream or response-protocol failure returns `500 internal_error` and releases the reservation when the billing service is available.

Repeating the same completed request with the same API key, `Idempotency-Key`, and body returns the stored response without another upstream call or charge.

## Errors

| Status | Error type | Meaning |
| --- | --- | --- |
| `401` | `authentication_error` | The API key is missing, malformed, or unknown. |
| `402` | `insufficient_credits` | The account cannot reserve the lookup cost. |
| `403` | `authentication_error` | The API key is revoked, expired, or lacks Contact Search access. |
| `409` | `idempotency_error` or `request_already_exists` | The key conflicts with another body, or the admitted request has no replayable response yet. |
| `422` | `invalid_request_error` | The content type, JSON structure, field value, or request size is invalid. |
| `429` | `concurrency_limit` | The user-level or service-level concurrent request limit was reached. |
| `500` | `internal_error` | An internal dependency, upstream request, protocol check, or settlement failed. |
| `503` | `service_unavailable` | Contact Search or the requested contact type is not enabled or priced. |

Errors use the standard [error envelope](/api-reference/errors).
