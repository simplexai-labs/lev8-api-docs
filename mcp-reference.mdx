Lev8 MCP lets your AI assistant search entities and contacts, answer research questions, enrich records, extract public lists, and manage credits through one hosted endpoint. There is no local server, executable, or package to install.

```text
https://app.lev8.com/mcp
```

[Create an API Token](/authentication) and set it as an environment variable, then click to install:

```bash
export LEV8_API_KEY="lev8_live_..."
```

## Connect your client

If you haven't created a Token yet, follow the [Authentication](/authentication) guide. Store the complete `lev8_live_...` value as `LEV8_API_KEY` in your environment.

<Warning>
  Never commit your Token to source control. The values below are placeholders.
</Warning>

<Tabs>
  <Tab title="Codex">
    ```bash
    export LEV8_API_KEY="lev8_live_..."

    codex mcp add lev8 \
      --url https://app.lev8.com/mcp \
      --bearer-token-env-var LEV8_API_KEY
    ```

    Confirm the server is registered with `codex mcp list`. Restart Codex after adding it so the new Tools are loaded. The ChatGPT desktop app, Codex CLI, and Codex IDE extension share this configuration on the same host.
  </Tab>

  <Tab title="Claude Code">
    ```bash
    export LEV8_API_KEY="lev8_live_..."

    claude mcp add-json --scope user lev8 \
      '{"type":"http","url":"https://app.lev8.com/mcp","headers":{"Authorization":"Bearer ${LEV8_API_KEY}"}}'
    ```

    The single quotes preserve `${LEV8_API_KEY}` for Claude Code to resolve when it connects. Run `claude mcp get lev8` to inspect the saved configuration, then use `/mcp` inside Claude Code to check the connection.
  </Tab>

  <Tab title="Gemini CLI">
    ```bash
    export LEV8_API_KEY="lev8_live_..."

    gemini mcp add --scope user --transport http \
      --header "Authorization: Bearer ${LEV8_API_KEY}" \
      lev8 https://app.lev8.com/mcp
    ```

    Run `gemini mcp list` to check the connection. Gemini CLI expands the environment variable when the command runs and saves the resulting header in your private user settings, so do not share that file.
  </Tab>

  <Tab title="Other">
    Lev8 MCP works with any client that supports remote Streamable HTTP servers. Point the client at `https://app.lev8.com/mcp` and send the Token in the `Authorization` header:

    ```http
    Authorization: Bearer lev8_live_...
    ```

    The config key for the URL varies by client:

    | Client | Config location | URL key |
    | --- | --- | --- |
    | Cursor | `~/.cursor/mcp.json` | `url` |
    | VS Code | `.vscode/mcp.json` (Command Palette > MCP: Open User Configuration) | `url` |
    | Windsurf | `~/.codeium/windsurf/mcp_config.json` | `serverUrl` |
    | Zed | Zed `settings.json` (under `context_servers`) | `url` |
    | Warp | Settings > MCP Servers > Add MCP Server | `url` |

    Most clients use the standard `mcpServers` shape:

    ```json
    {
      "mcpServers": {
        "lev8": {
          "type": "http",
          "url": "https://app.lev8.com/mcp",
          "headers": {
            "Authorization": "Bearer YOUR_LEV8_API_KEY"
          }
        }
      }
    }
    ```

    The Token is request-scoped. It is not a Tool input and does not appear in Tool schemas or results.
  </Tab>
</Tabs>

## Available Tools

- **`entity_search_create`**: Create a billed asynchronous search for companies, people, creators, Shopify stores, Xiaohongshu, or WeChat Official Accounts.
- **`entity_search_status`**: Check the progress of an entity search task.
- **`entity_search_fetch`**: Read one page of results from a completed or in-progress search.
- **`contact_search`**: Find an email or phone number. Only a non-empty result is charged.
- **`deep_search`**: Answer an open-ended research question synchronously.
- **`enrich`**: Generate structured fields from entity context and a caller-provided JSON Schema.
- **`extract`**: Extract social, GitHub, or public web-page lists synchronously.
- **`credit_balance`**: Read the available credits for your billing account.

See the [Entity Search](/api-reference/entity-search), [Contact Search](/api-reference/contact-search), [Deep Search](/api-reference/deep-search), [Enrich](/api-reference/enrich), [Extract](/api-reference/extract), and [Credit balance](/api-reference/credit-balance) API references for full parameter details.

## Try it

After the Tools appear in your client, ask it to use Lev8 in natural language:

<Accordion title="Example prompts">
  **Search for entities**

  ```text
  Use Lev8 to find 20 AI infrastructure companies in the United States.
  ```

  Calls `entity_search_create`, then `entity_search_status` and `entity_search_fetch` automatically.

  **Find a contact**

  ```text
  Find the work email for the VP of Sales at Example Company using Lev8.
  ```

  Calls `contact_search` and returns the result directly.

  **Research a question**

  ```text
  Use Lev8 Deep Search to explain who founded Mercury and distinguish the companies that share that name.
  ```

  Calls `deep_search`. Its `answer` is a dynamic, non-null JSON value and may include a generated result plus citations.

  **Enrich an entity**

  ```text
  Use Lev8 to enrich this company record with a summary and current CEO: Company: OpenAI, Website: https://openai.com.
  ```

  Calls `enrich` with an object JSON Schema for the requested fields.

  **Extract a public list**

  ```text
  Use Lev8 to extract company names and websites from https://example.com/directory.
  ```

  Calls `extract` with `type: web2list`, the public URL, and an extraction instruction.

  **Check credits**

  ```text
  Check my Lev8 credit balance.
  ```

  Calls `credit_balance`.
</Accordion>

Your client chooses the relevant Tool and asks you to approve the call according to its own permission settings.

## Entity Search workflow

Entity Search is asynchronous. Create a task, monitor it, then fetch results in pages.

<Steps>
  <Step title="Create">
    Call `entity_search_create` with an `entity_type` and `objective`. For `xiaohongshu` searches, or WeChat Official Account searches with `entity_type: "wechat"`, set `enable_web_search` to `true`. Save the returned `leads_search_id`.
  </Step>
  <Step title="Monitor">
    Call `entity_search_status` until the state becomes `done` or `error`. You can begin fetching as soon as `ready_count` is positive. Xiaohongshu and WeChat Official Account tasks usually take 1 to 2 minutes before results are ready.
  </Step>
  <Step title="Fetch">
    Call `entity_search_fetch`. Advance `pts` by the returned `count` until all `ready_count` results have been read.
  </Step>
</Steps>

<Tip>
  A task with `status: error` can still have ready results. Fetch them before closing the task.
</Tip>

## Contact Search workflow

Contact Search is synchronous and returns the result in a single call.

<Steps>
  <Step title="Search">
    Call `contact_search` with a `contact_type` (`email` or `phone`) and an `objective` describing one requested contact, the company, and known identity evidence. Supply a stable `idempotency_key` before sending the request. The result is returned directly. The optional `timeout_seconds` sets the total response budget, from 10 to 600 seconds; the default is 120.
  </Step>
</Steps>

A `found` outcome with a non-empty contact value is charged. `not_found` and `error` consume zero units. A charged candidate is not necessarily bound to the requested owner.

For email, inspect `assessment`, `search_summary`, and `next_action` when present. If `same_input_retry=not_recommended`, do not repeat the search with only a reworded objective or a new key. Obtain the specified new evidence, review the bounded `alternatives`, or end the search. Missing or partial coverage is not proof that no contact exists. See [Email search guidance](/api-reference/contact-search#email-search-guidance).

## Synchronous tools

`deep_search`, `enrich`, and `extract` each return a result in one Tool call. Deep Search passes through its `answer` as dynamic JSON; do not assume it is always a string or that an object has fixed fields. Enrich returns an object shaped by the supplied JSON Schema. Extract returns an array on success and a failure-reason string when `success` is `false`.

For `web2list`, `extract` requires an instruction and a public HTTP or HTTPS URL. Social and GitHub extraction limits default to `100` and can be at most `10000`; `web2list` normalizes the limit to `100`.

## Billing and retries

Every Tool call goes through the Lev8 API, so [Token scopes](/authentication), [credit billing](/guides/billing), and [idempotency handling](/guides/idempotency) still apply.

`contact_search` accepts an optional `idempotency_key` and returns it with the result. If omitted, the server generates a key. The other paid POST Tools generate their keys internally.

<Warning>
  For `contact_search`, reuse the same key and input after a disconnect to recover a completed result without new work or charges. A completed error is also replayed; the same key does not rerun a failed search. An intentional new search requires a new key and can incur a new charge. Do not create a new request while the original outcome is unknown.
</Warning>

## Troubleshooting

<Accordion title="The server returns 401 Unauthorized">
  Confirm the Token is complete, active, and sent as `Authorization: Bearer <token>`.

  ```http
  Authorization: Bearer lev8_live_...
  ```
</Accordion>

<Accordion title="Tools do not appear">
  Restart your client after changing its MCP configuration. Some clients require a full restart to detect new MCP servers.

  Check the MCP server list or connection logs in your client to confirm `lev8` is registered.
</Accordion>

<Accordion title="A Tool reports a scope error">
  Enable the required scope on your Token from [API Tokens](https://app.lev8.com/api-tokens), or create a new Token with the correct access.
</Accordion>

<Accordion title="A paid Tool times out">
  Do not immediately call it again. The original operation may still have consumed credits. Check with `entity_search_status` or `credit_balance` before retrying.
</Accordion>

<Accordion title="Cursor cannot read the Token">
  If Cursor was opened from the macOS Dock or another desktop launcher, that process may not have access to `LEV8_API_KEY`.

  Launch Cursor from a terminal where the variable is exported, or configure the variable in your desktop environment.
</Accordion>

<Accordion title="Transport details">
  - Lev8 MCP uses **Streamable HTTP** (`POST` with JSON). The endpoint is stateless and does not create persistent sessions or send server-initiated notifications.
  - Authentication uses the `lev8_live_...` API Token as a Bearer credential. The HTTP API and MCP use the same Token.
  - OAuth, dynamic client registration, and browser authorization are not supported in the first release.
  - The MCP endpoint does not provide Token creation, listing, or revocation Tools.
  - Objective text, results, contact details, and Tokens are not written to MCP logs.
</Accordion>
